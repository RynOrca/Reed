# Reed 一苇

![Reed 一苇](https://raw.githubusercontent.com/RynOrca/Reed/main/.github/assets/logo.png)

**一苇以航，轻渡学海。**

Reed 是一款面向学习与日常工作的独立 Windows 桌面 Agent。它以快捷键唤出的轻量窗口承载对话，把角色、学习流程、长期记忆和 Obsidian 笔记连接起来，让提问、练习与复习能够接续进行。

Reed 基于 PI Agent 构建，使用 Tauri 与 WebView2 提供桌面界面。当前版本为源码与 Windows 便携构建阶段。

## 主要能力

| 能力 | 说明 |
| --- | --- |
| 轻量桌面窗口 | 无系统标题栏、圆角、托盘驻留、全局快捷键、窗口置顶；主窗与设置窗分别记住大小和位置 |
| 模型配置 | OpenAI / Anthropic 兼容接口；模型发现、上下文上限、推理协议与视觉能力可编辑 |
| 对话与附件 | Markdown、表格、图片粘贴与预览、本地文档链接；右侧消息标记快速跳转；回复时发送默认排队，可将队列项转为引导 |
| 上下文与速度 | 上下文占用圆环、自动和手动压缩、角色与模型及思考档位展示；截断异常有界恢复；接口返回 token 用量时显示 tok/s |
| 角色与技能 | 内置 Agent、Planner；角色说明注入系统提示词，可绑定独立技能文件并设置必须使用 |
| 项目学习目标 | Markdown 管理大目标、阶段与任务进度；右上书本展开全高面板，用户编辑、Agent 只读 |
| 学习画像与工作记忆 | 角色独立开启学习画像；工作经验另设开关；模型先审查长期价值，再合并相似内容，详情按需召回 |
| Obsidian 笔记库 | 首次连接生成科目与目录总览；从 Markdown 笔记中查找相关段落，引用原文件和行号 |
| 工具与扩展 | 文件工具、独立浏览器、当前时间、Tavily 搜索与正文提取；MCP 按需发现和调用 |
| 权限与审批 | 工作区写入边界、自定义只读目录、完全文件权限；自动审批 / 手动确认 |
| 外观 | 两套原画图标，支持浅色、深色和跟随系统；启动首屏展示 Reed 一苇 |

## 开始使用

1. 从源码构建便携包，运行其中的 `Reed.exe`。保留 `agent/` 和 `runtime/` 文件夹与程序在一起。
2. 打开设置 → 模型，选择提供商或自定义接口，填写 Base URL、API Key，获取模型列表。
3. 编辑模型，确认上下文上限、推理能力与视觉支持。接口没有返回的能力需要手动补充；发送图片前请启用支持视觉。
4. 在输入区点击 **Model**，选择模型、思考档位并确认；点击 **Role** 选择角色。
5. 可选：设置项目目录，在角色编辑中开启学习目标或学习者画像；连接 Obsidian Vault、导入技能、配置 Tavily 或 MCP。

默认思考档位为 `off / low / medium / high / xhigh`，默认选择 `off`。这些默认选项不代表服务器声明支持全部档位，实际行为取决于模型服务及其推理协议。

更新时先通过托盘退出旧版，再启动新版。用户配置与聊天保存在程序目录之外，替换便携包不会重置配置。

## 学习流程与角色

角色负责回答原则，技能负责具体步骤。角色编辑中可绑定技能并开启“必须使用”。技能正文保持为独立 `SKILL.md`，便于编辑、更新和复用。

内置三个流程：

- **教学**：确认学习目标和基础 → 讲解与示例 → 理解检查 → 总结与记录。
- **练习生成**：确定考点与难度 → 生成练习 → 收集作答 → 反馈与错因 → 后续练习。
- **间隔复习**：找出待复习概念 → 先回忆再揭示 → 判断薄弱点 → 更新记录 → 安排下一次复习。

按需绑定只把名称和说明提供给 Agent，相关任务再读取正文。必须使用的绑定会在匹配流程开始前由程序加载正文，技能停用或读取失败会阻止该流程。自定义流程可用 `/skill 技能名` 明确启动；不会每轮加载全部正文。角色指令进入系统提示词，Planner 的修改工具由程序禁用；模型本身的回答仍需要结合实际输出检查。

## 项目学习目标

在角色编辑中开启学习目标，选择项目后点击对话窗口右上角的书本图标。目标面板从右侧展开，覆盖整个窗口高度；右上角可编辑 Markdown，底部显示项目和路径。任务使用圆形勾选控件，进度根据 Markdown 任务列表计算，滚动时隐藏滚动条。

大目标、阶段、小任务均由 Markdown 表达，例如：

```markdown
# 掌握操作系统基础

## 第一阶段：进程与线程
- [x] 理解进程和线程的区别
- [ ] 用自己的话解释上下文切换

## 第二阶段：内存管理
- [ ] 理解分页与虚拟内存
- [ ] 完成章节练习
```

每个项目对应独立的 `.md` 文件，保存在应用数据目录的 `learning-goals/` 下，文件头记录项目名称与路径。同名但路径不同的项目相互独立；外部编辑发生冲突时会要求重新加载，保留当前草稿。用户负责编辑与勾选，Agent 不能修改目标文件。角色开启后，每次对话模型请求都会注入当前项目的最新目标；关闭后不向 Agent 提供目标内容。

## 记忆如何工作

学习者画像与工作经验分别控制：

| 类型 | 保存内容 | 开关与读取方式 |
| --- | --- | --- |
| 学习者画像 | 明确的长期目标、稳定偏好、有证据的重要学习进度与反复困难 | 角色编辑中开启；关闭后停止学习记忆的记录、后台整理、注入与召回 |
| 工作记忆 | 工具验证过且可复用的命令修正、常用路径和操作流程 | 记忆设置中的独立开关；关闭画像仍可使用 |

即时保存和后台整理都会先调用当前模型审查证据、持久性与复用价值，通过后才去重、补充已有条目。普通问答、助手讲解、临时路径、偶发失败与未验证方案应跳过；一次提问不代表不会，一次答对不代表掌握。不确定、模型调用失败或用户取消时不保存。明确要求“记住”优先处理，但仍需可靠证据；明确要求本会话不写记忆时禁止保存。

默认上下文只提供简短学习状态、相关工作经验与资料索引，详情通过 `recall_memory` 按需读取，不自动注入跨会话历史原文。待复习条目只有在实际加载绑定的 `spaced-review` 技能后才能披露。既有记忆和用户手动编辑保留，自动筛选效果取决于所选模型。

## 笔记库总览与对话导航

首次连接笔记库时，Reed 遍历 Markdown 文件，将目录、标题和正文抽样分批交给当前模型，生成科目、文件夹用途、代表笔记与检索入口。在笔记库根目录创建 `Reed-笔记库总览.md`，之后可作为定位笔记的导航。已有总览不会自动覆盖；失败后可重试。这个过程浏览全库的文件结构与内容抽样，并非逐字精读所有笔记；超限或无权读取的文件会在总览列明。

关闭按钮旁的置顶图标可让窗口保持在其他窗口上方。对话右侧居中的短线标记对应每条用户消息，点击即可快速定位，位置与右上角学习目标入口分开。

## 长对话与异常恢复

Reed 为模型输出预留上下文预算，在必要时压缩历史，并保留原始任务、仍适用的用户要求、文件路径与实际验收结果。过长工具结果以摘要和可按需读取的完整结果保存，压缩失败时保留原上下文。

遇到只思考而无正文的长度截断或特定流式数据异常时，程序会进行有次数限制的恢复，并在界面记录中断与最终状态；连续失败不会无限重试。网页生成任务在具备视觉能力和浏览器工具时包含截图与评审检查，未完成验收会明确标记。它们用于提高任务可见性与可靠性，不能保证任意模型持续发送进度说明或正确评价视觉效果。

## 数据与权限

- 配置存储在 `%APPDATA%\Reed\user-config.json`。首次启动会自动迁移旧目录并保留旧目录作为备份，不覆盖已有 Reed 数据；提供商、加密凭据、角色、技能、笔记库、MCP 与桌面偏好集中保存。
- API Key 在 Windows 上使用当前用户的 DPAPI 加密。加密配置不能直接作为跨账户迁移凭据使用。
- 会话、记忆、学习事件、项目目标、附件和窗口状态保存在独立数据文件中。笔记库索引读取 Vault 原文件，不修改原笔记；初次总览在库内新建 `Reed-笔记库总览.md`。
- 默认允许读取其他位置的文件，写入限制在当前工作区；自定义只读目录禁止修改。只有完全文件权限可解除这些写入限制。
- 未隔离的 bash / PowerShell 已关闭。文件范围限制不是操作系统进程沙盒；外部 MCP 进程和调用要求完全文件权限，并遵循审批设置。
- 模型请求会把对应对话、附件以及召回内容发送给所选服务；Tavily 和远程 MCP 请求会访问配置的服务。服务费用及数据处理规则由各提供商决定。

## 从源码构建

当前桌面实现主要支持 Windows。准备：

- Node.js **22.19 或更高版本**、npm；
- Rust stable；
- Visual Studio C++ 构建工具及 Windows SDK；
- Microsoft Edge WebView2 Runtime。

在仓库根目录运行 PowerShell：

```powershell
npm ci --prefix desktop/agent
./desktop/tools/package-portable.ps1 -Output ./dist/Reed-portable
```

输出目录包含 `Reed.exe`、内置 Node 运行时和 Agent 依赖。脚本不会覆盖已有输出目录，会为新构建添加时间后缀。

图标的运行资源已经包含在源码中。需要从原画重新制作透明图标时，安装 Pillow 后运行：

```powershell
python desktop/tools/extract-icons.py
./desktop/tools/generate-icon.ps1
```

透明蒙版仅改变边缘 alpha，保留圆角块内原画；PNG 和多尺寸 ICO 供窗口、托盘与 Windows 程序使用。系统文件管理器显示默认写实浅色图标，运行中的窗口和托盘随应用外观切换。

## Windows 安装包

从 [最新版本](https://github.com/RynOrca/Reed/releases/latest) 下载 `Reed-0.2.0-setup.exe`。安装包包含 Node 运行时与 Agent，支持当前用户安装、开始菜单与卸载入口。升级和卸载默认保留 `%APPDATA%\Reed` 中的配置与会话；更新前从托盘退出旧版。也可以下载便携 ZIP，解压后运行 `Reed.exe`。

本 README 的功能介绍以当前 `main` 分支源码为准，已发布安装包包含的功能以对应发行说明为准。

从源码生成安装包与便携 ZIP：

```powershell
npm ci
./desktop/tools/package-installer.ps1
```

产物包含 SHA256 校验文件。安装包目前没有数字签名。

## 测试

```powershell
npm test
```

自动测试使用临时数据和本地模拟接口，覆盖模型、图片、文件范围、审批、记忆、笔记库、MCP、角色与技能绑定。

最近验收：86 项后端回归通过，记忆取消保护追加后 14 项专项复验通过；学习工作区桌面专项 9 项、综合桌面验收 36 项通过。模拟接口验证程序行为，真实模型的价值筛选、语义合并与视觉判断准确率仍需结合实际使用观察。

桌面验收需要 Playwright，并设置其模块路径和已构建便携包路径：

```powershell
$env:SUMMON_TEST_PACKAGE = (Resolve-Path ./dist/Reed-portable).Path
$env:SUMMON_PLAYWRIGHT_PATH = '<Playwright 模块绝对路径>'
node desktop/tools/desktop-acceptance.cjs
node desktop/tools/window-state-acceptance.cjs
node desktop/tools/learning-workspace-acceptance.cjs
```

桌面脚本使用隔离程序副本与用户数据，仅启动和终止自己的测试实例。真实模型验收是显式选择的单独脚本，必须通过 `SUMMON_LIVE_URL` 与 `SUMMON_LIVE_MODEL` 提供测试服务；源码不预设私人地址。

## 源码结构

```text
desktop/
  agent/       PI Agent SDK 桥接、模型、学习、工具与自动测试
  agent/skills/ 独立教学、练习和间隔复习流程
  src-tauri/   原生窗口、托盘、快捷键与进程宿主
  web/         对话与设置界面
  design/      原始品牌图标
  tools/       便携构建、透明图标提取与桌面验收
PLAN.md        当前计划与后续事项
CHANGELOG.md   变更记录与 Git 版本标签
NOTICE.md      第三方来源与许可证说明
```

仓库维护 Reed 独立桌面应用。依赖、用户配置、API Key、会话、附件、日志和构建产物不应上传，已在 `.gitignore` 中排除。

## 当前限制与后续计划

- 笔记检索使用本地关键词匹配，尚未提供向量检索。
- MCP 支持 stdio 与 Streamable HTTP，尚未提供 OAuth 登录。
- 生成中的队列目前只支持文本消息。
- 已有模拟接口和隔离桌面验收；真实 Tavily、用户 MCP、Windows 重登自启仍需按实际环境验收。
- 尚未提供自动更新及更多平台支持。
