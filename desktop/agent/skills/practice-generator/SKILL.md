# 练习生成

1. 确认知识点、难度、题量和形式，优先使用用户当前要求；没指定时从一个基础题开始，避免一次布置大量题。
2. 有相关笔记时通过 search_notes 确认定义和范围，引用来源。题目需可作答且有明确判定依据。
3. 先给题目和必要条件，暂不展示答案，等待用户回答。若用户明确要完整题库及答案，则按要求把解析放在独立一节。
4. 检查答案及推理，指出正确部分和具体错误；优先给提示，让用户有机会修正。不要仅凭答案长度判断掌握程度。
5. 需要时给完整解析，并提供一道针对错误的迁移题；难度根据实际作答调整。
6. 总结本次练习的证据和待加强点；用 record_learning_event 的真实参数记录能够引用用户原话的概念或误解。没有作答不得记录已掌握或完成。

不自动写入用户笔记或创建练习文件，除非用户要求且权限允许。不要在用户作答前替用户填写答案。


正文表达（show_learning）：它是工具，必须在回复过程中发起真正的函数调用，参数是 JSON 对象；把 `<show_learning ...>` 或 `blocks="[...]"` 当文字写进正文是错的，用户只会看到一串代码。用法是在同一轮里交替排列：Markdown 题干 → 调用工具放图解或提问 → 继续讲解，不要把所有块堆在回复末尾。每轮最多 8 块，其中 choices/fill 合计最多 1 个。

按内容选择块（详见 learning-blocks 技能）：
- 顺序、因果、数据流 → flow（`nodes[{label,value,note?}]`，时间线加 `layout:"timeline"`）。
- 易混概念并排比较 → compare（2–3 列，比较维度一致）。
- 输入/中间量/输出与不变量 → result（`items`，可选 `conclusion`）。
- 分步推导，公式配依据 → derivation（`steps[{expression,reason}]`，expression 用不含分隔符的 LaTeX）。
- 易错点、适用条件 → callout；默认折叠的线索 → reveal（展开不发消息）；术语就地解释 → term。

提问必须用组件，不要在正文里写“你觉得呢？”再等用户打字：
- 选择题用 choices，每个选项的 replyText 是用户会真实说出口的完整句子；一次只问一个问题，不预写判题反馈。
- 填空题用 fill：单个输入框，`label` 标明要填的字段或等号左侧，`multiline` 可选；用户点“提交回答”才作为用户消息发送，不自动执行用户输入代码。

出题时不要在用户作答前把答案或解析放进同一个块。用户要求直接解释或跳过练习时尊重其选择。展开提示、自报“懂了”或选择偏好均不自动成为掌握证据，学习记录继续遵循已有权限与证据规则。**只把真正的数学写成 LaTeX**；字段名、API 参数、函数名、路径和代码用反引号（如 `raw_content`、`followup_questions`），不要因为有下划线就写成公式。数学格式：题干、选项、`fill.label` 与所有组件字段的行内公式用 `$...$`，独立公式用 `$$...$$`，推导 expression 用不含分隔符的 LaTeX；不要写 `c1*c2 mod n^2` 这类纯文本公式，也不要用全角 `＝`。不要输出 HTML 或脚本。需要来源时只使用检索返回的原始 summon-file URL 与行号，source.label 说明笔记和位置，不编造来源。
