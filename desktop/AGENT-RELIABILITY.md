# 上下文与网页视觉验收

## 上下文管理

Reed 使用 PI 的会话压缩，增加按模型计算的预算与检查点保护。模型的 `contextWindow` 与 `maxTokens` 分别表示上下文窗口和输出预算，不能用其中一个推断另一个；不同服务的输出参数语义仍由适配器决定。

- 输入预算预留输出上限和安全余量。系统提示和工具定义也计入估算；图片使用单独估算，估算不是提供商的精确计数。
- 提交新消息前检查历史和新增内容，必要时先压缩。单条消息本身过大时明确拒绝，不静默裁切用户要求。
- 大工具文本完整保存在 `%APPDATA%/Reed/context-artifacts/`，模型收到首尾文本、收缩标记及完整文件路径。图片不作文本裁切。
- 旧工具结果只在模型上下文投影中进一步收缩，近期工具调用与结果仍保持对应关系。
- 摘要保留目标、约束、纠正、进展、未完成事项和实际验证结果。摘要为空、取消、异常或长度截断时取消检查点，保留原历史。
- 原始用户要求中的会话禁写记忆指令会阻止 `remember` 和后台整理，压缩后仍检查原始记录。这是会话级保护；跨会话的项目记忆开关尚未实现。
- 诊断记录预算、估算和压缩原因；不会在诊断记录中保存完整摘要或用户消息。

参考 Hermes 的旧工具结果收缩和近期上下文保护，以及 Codex 的独立上下文、自动压缩与工具输出预算。具体实现仍使用 PI 公开扩展接口，不修改依赖代码。

## 网页截图与评审

模型需启用图片输入，工具设置需开启浏览器。Reed 按需启动独立、无界面的 Edge，不操作用户已有浏览器标签页。

1. 用 `browser` 的 `preview` 和 `path` 打开本地 HTML，或用 `navigate` 打开开发服务器 HTTP(S) 地址。
2. 用 `screenshot` 获取桌面与窄屏图片；例如 `viewport: {width:1280,height:800}` 和 `{width:390,height:844}`。动画设置 `waitMs:1000` 或更长，再检查运行后的画面。
3. 截图作为真正的图片内容进入下一次模型请求，同时保存 PNG 文件、尺寸、时间及本地产物加载版本。
4. 模型查看图片后调用 `visual_review`，提交逐项需求检查、证据、问题和通过结论。
5. 发现问题则修复、重新预览、重新截图和评审。新文件内容会使旧评审失效；旧页面截图不能证明新版本通过。

截图证据位于 `%APPDATA%/Reed/artifacts/screenshots/`，评审存入会话记录。截图上限 5 MB，等待上限 10 秒；完整页面还有尺寸和像素限制。

网页相关文件写入或编辑后，模型提前结束会被要求继续验收。每轮最多 6 次评审、8 次完成前提醒；浏览器或图片输入不可用、运行失败或达到边界时，显示“尚未通过验收”和剩余原因。已知问题不能被标为通过。

“通过”是模型基于截图的评审结论。它不保证视觉判断没有遗漏；交互行为、可访问性和业务逻辑还需要相应功能验证。本地 HTML 和开发服务器预览均支持，原生应用窗口截图尚未接入。

## 回归验证

测试仅使用临时数据、本地模拟模型服务和隔离 Edge。覆盖连续压缩、残缺摘要拒绝、工具关联、完整文本恢复、实际截图、图像进入模型请求、修改后旧证据失效与有界停止。模型实际审美与判断准确率需在真实任务上持续评估。
