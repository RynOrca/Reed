- 设置→模型→编辑提供商，新增“允许并行请求（实验性）”。默认关闭，旧配置未填写时串行；开启后最大并发数2–8，默认2。配置落盘并重启恢复，旧客户端保存时保留既有选项。
- 同一Base URL（规范化origin+path并去尾斜杠）共用额度，不按模型名或提供商条目拆分；重复配置采用最小额度。不同地址独立。不同域名别名或不同/v1路径不自动推断为同一底层引擎。
- 主对话流式请求、上下文压缩和Reed runtime.completeSimple辅助请求使用同一调度。经验/学习整理、其价值审查和总览标记后台；等待中的前台优先，组内FIFO。已开始的请求不会被优先级强行抢占。
- 每地址最多32个等待请求，超额明确报错；排队取消移除且不发起请求。活动调用保留额度至底层返回/流最终result结束，流消费者提前退出不冒充服务完成。
- 额度只覆盖单次推理请求，主模型返回工具调用后即释放；工具内扩词/审查可再获取，避免持有整轮对话造成嵌套死锁。仅消费result的压缩路径也能正确释放。
- 主回复排队时显示“正在等待模型服务空闲…”。没有新增常驻服务或数据库；只维护进程内小队列。打包模块清单补入model-requests.mjs。
