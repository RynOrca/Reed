## 建议的最小下一阶段

先把阶段定义为“按证据提升笔记检索与引用可信度”，不另建知识服务，不重构记忆架构。

1. **触发与顺序**：有 Vault 且用户问题涉及库内主题时，先做本地 FTS；明确要求查笔记或回答依赖个人资料时主动查。只有本地零命中，或隔离评测定义的低置信情形，才调用现有规划器扩展最多 3 个知识点词。扩展失败/超时继续用原查询结果，不重试风暴。总览只帮助定向，回答依据始终是本地原文。
2. **索引更新/失效**：继续采用检索时扫描、未变正文不重读的轻量路径。每轮扫描明确收集本轮成功检查过的文件；只对成功完成的 Vault 扫描执行 retain。遇到目录不可达、权限错误或预算中止时保留旧索引并报告索引可能陈旧，避免不完整扫描把未遍历尾部笔记批量删出索引。可考虑用内容哈希对已变文件确认版本，先以测得的元数据漏更/扫描耗时决定是否需要，避免无差别读全库。
3. **查询与引用**：保留最多 6 段和原文件行号 URL；回答只对实际支持的主张引用对应段落。评测分开计数：命中段落相关率、引用链接可打开率、引用支持主张率、无结果时不虚构。若真实模型经常漏引或错引，再加轻量回答后检查/格式校验，不先引入向量检索。
4. **画像与复习衔接**：画像保持角色功能开关 + L1 双重门控，用户明确原话和来源时间作为记录前提。只把明确掌握/完成的用户陈述视为进展；“学过”仍是待复习，未知掌握度继续为 null。纠正用 replace 指向旧主题，保留事件历史。待复习条目仅在必选 `spaced-review` 正文成功加载后暴露；复习中先提示回忆，完成后按用户明确结果记录，不能因模型讲完就标记掌握。
5. **定向验收**：使用隔离 Vault 与固定查询集，至少覆盖同义词、中文/英文混合、编辑、重命名、删除、权限拒绝、Vault 失联/部分扫描、索引重开；核查原文段落和行号。真实任务记录首个检索动作、引用对应关系、是否无根据声称、端到端延迟及扩词是否发生。建议门槛：变更/删除在下一次成功扫描后无旧命中；无关段落不得因扩词替换成唯一首选；引用路径/行号可解析且引用支持主张；故障不清空旧索引；扩词只在触发条件下发生且单次不超过 8 秒。设基线后再定命中率阈值，避免凭空给出当前不存在的数字。

## 应暂缓的工作

- 向量数据库、embedding 模型、独立常驻服务：目前没有召回证据证明 FTS + 有界主题展开不足，也没有已部署 embedding 服务。
- Vault 全量后台 watcher、自动重建索引和复杂队列：先测现有按查询扫描在真实库上的成本与陈旧问题。
- 全库自动摘要/重写原笔记：检索阶段只读原文；总览继续作为导航，用户原文不可被自动改写。
- 泛化的“记忆智能体”或替换现有工作经验/画像生命周期：已有独立开关、事件修订和来源证据；本阶段只验证知识检索与画像消费的交界。
- 以模型自报“已引用/已掌握”作为验收：需核对引用指向的原段落及用户证据。

## 收益与风险

预期收益是用更少模型调用获得可核验的个人笔记答案，并让学习画像只影响相关主题，复习权限保持明确。主要风险是目录扫描失败时误删索引、弱命中被扩词噪声污染、以及模型给出看似规范但不支持主张的引用。先解决失败状态保留和建立真实评测基线，收益明确后再决定向量或后台索引方案。
