## 单请求服务的软件竞争风险：已复现

`desktop/tools/single-request-contention.mjs`使用真实createMemoryAgent与workMemoryExtension调度代码、模拟completeSimple、合成明确常用目录及read工具证据，不触碰真实资料、不发送推理请求。按bridge轮末行为先启动经验整理，再schedule学习记忆整理；模拟经验整理超过2.5秒后，学习记忆整理也发起调用，峰值并发为2。报告 `dist/real-memory-acceptance/single-slot-contention.json`。

代码路径：bridge完成回复后memoryAgent.schedule与void workingTools.consolidate；前者2.5秒timer，后者满足有真实工具证据且明确请求或修正验证时立即调用模型。两条路径没有统一端点队列，因此在单槽服务上可能排队或被拒绝。该竞争已在模拟服务复现，不代表前述无工具纯回复慢样本就是由它造成；纯回复没有满足工作经验整理条件且学习画像关闭。

新用户prompt会取消学习整理，工作经验before_agent_start也取消旧整理，但AbortSignal只表达客户端取消，无法在没有服务日志时保证远端计算立即终止。笔记扩词5秒回退同样不能证明引擎已释放单槽。总览生成独立启动，还可能与后续主对话竞争。上述均是需要纳入统一调度的路径。

## 网络和远端可观察边界

配置端点是组网主机而非本机回环。仅探测该服务端口3次，含DNS的TCP建连992.4/113.7/115.7毫秒；tailscale ping限定3次，均经DERP(sin)，往返233/237/240毫秒。与推理实验时刻不同，不能当作当时完整网络trace。中继会增加网络成本，但同路径约1秒回复已证明它不是每次必然十几秒等待的充分解释。

已配置SSH连接不对应模型服务机；未登录无关主机，也未改变远程服务。没有ninfer启动参数、队列/缓存/加载日志和取消处理收据，因此不宣称已查明服务内部根因，也不推测具体ninfer配置选项。

## 建议顺序

1. 先修软件中确定的竞争问题：按实际端点建立统一有界调度，单槽服务最多一个活动推理；主对话优先于尚未开始的后台整理，排队取消不发请求，明确已有请求的取消边界。范围覆盖主对话、总览、检索扩词、经验/画像整理和价值审查；避免工具内辅助请求的嵌套调度死锁。
2. 用模拟单槽服务验收连续对话、两种整理、总览与扩词取消，不向真实Qwen并发压测。保留整理内容和证据门控，不静默丢弃保存任务。
3. 如可获得远程部署信息，再只读核对模型加载/首请求、提示词缓存、队列、流式flush及客户端取消日志；决定是否改变引擎参数或主模型服务。
4. 独立快速辅助模型仍是备选，可以把扩词/整理负载移出单槽Qwen；它不能解释或自动消除纯主请求的首次等待。本轮仅诊断，未实现调度或辅助模型配置。
